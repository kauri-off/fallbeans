# Состояние: с чего продолжать

Перезаписывается целиком в конце каждого треда. Только то, чего не видно в коде и git: где остановились, что
начато и не закончено, что сломано, с чего начать.

**6 октября 2026**, ветка `master`, последний коммит — `b4f32a6` (оверлей F4, записи F9, профайлер).
Версия `0.1.0-alpha.1`. Последний TS-коммит помечен тегом `ts-final`. Протокол 20 (в этом треде не менялся).

Не закоммичено — оптимизация рендера, первый проход (протокол и симуляция не менялись):
- Запись F9/бенчмарк делится по сценам (`segments`: меню, лобби, карта, подиум; `perf show` — таблица сцен);
  `--perf-from-start`; `--start a,b,c` — игра из нескольких карт по очереди.
- Фризы загрузки: картинки порталов (было 866 мс на входе в portal-panic, 124 мс в лобби) — отрезки спирали
  растеризуются в своей окрестности (тот же результат, тест) и кэшируются по цвету на всю игру; `face::make_kit`
  (80 мс) — фоновая задача, лучи с отсевом по рамке (тест); детальные текстуры поверхностей (17 × 2–8 мс) — в фоне
  с запуска. На 5070 длинных кадров при смене сцен не осталось, кроме двух на старте приложения.
- Материалы спецобъектов — по содержимому детали, не по предмету: portal-panic 1305 → 324 материала, рендер-поток
  4,75 → 4,21 мс.
- Шейдер поверхностей: узор и математика детали — только когда нужны (ветвление по униформе). Пресет Low не
  читает детальную текстуру (`Surfaces::set_plain`) и без виньетки: на встройке Radeon 610M (GL, 1600×900) лобби
  8,65 → 7,5 мс GPU, раунд jump-club ~12 → ~10 мс.
- Профайлер выключенный пропускает чужие спаны по id без поиска (кадр 4,52 → 4,44 мс на 5070).
- Intel Gen9 + Mesa 26.2: зависание GPU (`GPU HANG`, «preemption time out», IPEHR = 3DPRIMITIVE) через ~3 с любой
  сцены с картой — и Vulkan, и GL, при любых настройках графики и без декора/пропсов/спецобъектов/лиц/неба/ботов.
  `INTEL_DEBUG=reemit` убирает (разницы в кадре нет); клиент на Linux сам перезапускается с ним
  (`quality::intel_gen9_relaunch`, `unsafe` в проекте запрещён — `set_var` нельзя). В 26.2.4 исправления нет.
- Паника `clock::steer` (запас ввода < 0 после долгого кадра → Lightyear: «cannot convert float seconds to
  Duration») — запас прижат к нулю. Её же ловил нестабильный `scenarios::the_owner_leaves_the_lobby`.

Тестовый слабый ноутбук автора — `ssh huawei` (i5-10210U, Intel UHD CML GT2, 7,5 ГБ, EndeavourOS, Mesa 26.2.3,
KDE Wayland; окна там запускать можно, sudo без пароля). Бинарники сборки `perf` копируются tar'ом по ssh в
`~/fb-perf/new/` (rsync здесь нет; `assets` рядом), скрипты: `run.sh` (offscreen), `win.sh` (окно, профиль `win`,
настройки игрока), `wl.sh TAG key=value…` (лобби 35 с с записью), `wset.sh`. Удалённая оболочка — zsh.

Цифры huawei (окно 1280×720, Medium, без vsync): лобби 38 fps, jump-club 48, portal-panic 34; упор — CPU рендер-
потока (лобби: рендер 27 мс = граф 11,7 (запись проходов 7,8, отправка 2,9) + ожидание swapchain ~5 + ~11 мс мелких
систем подготовки), main ~11 мс, GPU 15–19 мс. Low без теней — 42 fps. До 60 fps нужно −40% и CPU, и GPU.

Постоянного сервера нет: игроки добавляют свой сервер в список на главном экране (`README.md`, «Свой сервер»).
У автора сервер стоит из `.deb` (systemd, логи в journald).

Не проверено вживую: оверлей F4 в окне, вид Low без детальной текстуры и виньетки (автор смотрит сам), лица бобов
после переноса в фон (появляются на кадр-два позже первого боба), `--start` из нескольких карт с `--fill` в окне.

## Начать с

1. CPU рендера — число отрисовок: в лобби 2944 меша (видно ~450), в portal-panic 3161. Объединить статическую
   геометрию карты (примитивы, декор) в крупные меши по материалу; мерить на huawei (`wl.sh`) и `perf compare`.
2. Main ~11 мс на huawei: `PostUpdate` 5 мс (трансформы, UI, видимость) — тоже от числа сущностей.
3. GPU на встройке: основной проход ~70% кадра. Кандидаты — prepass глубины на Low (−0,45 мс на 610M),
   масштаб рендера по умолчанию для T0/T1 (FSR quality: −2–4 мс), решения за автором.
4. Профайлер встроенный стоит игроку ~0,2 мс (4%) даже выключенный: включать спаны систем флагом при старте? Решает
   автор (F4-профайлер тогда только после перезапуска с флагом).
5. Шквал откатов в portal-panic с автопилотом (789 откатов / 51 549 тиков за минуту, main 8–11 мс) — не рендер,
   предсказание телепортов.
6. Прежнее: поиграть на новой сборке (60 Гц снимков), `fuzz-ui`, автообновление на втором релизе, предложения
   аудита (`docs/audit/proposals.md`).

## Не закончено и известные странности

Проблемы, описанные в `README.md`, здесь не повторяются.

- Иконка окна не задана (Bevy рисует свою): в Windows на панели задач и у exe нет иконки игры, ярлыки NSIS — с
  иконкой. На Linux иконка берётся из desktop-файла по app id `io.github.kauri_off.fallbeans`.
- `DeviceLost` клиент игроку не объясняет — выходит молча.
- `cargo xtask assets --export` пересобирает модели из Blender (AO вшивается серым PNG, у TS был JPEG — файлы
  чуть больше); закоммиченные модели — ещё из TS-конвейера, пересборка отложена автором.
- Допуски баланса ботов в `baseline.json` у карт на выживание широкие (первое выбывание ±5–9 с): разброс между
  сидами там большой, мелкие сдвиги ощущения на них база не поймает.
- `cargo xtask dist flatpak` добавляет пользовательский remote flathub (`--if-not-exists`).
- В соло-игре раунд кончается, как только единственный человек финишировал или выбыл: зрителя проверять двумя
  клиентами.
- Стресс с ботами в dev-сборке не проходит порог тика: гонять с `--release`. Первый прогон стресса сразу после
  сборки иногда ловит общее замирание на 0,1–0,6 с — повторить. У каждого клиента одна «необъяснённая»
  расходимость через ≈200–245 тиков после старта (в пределах порога); с прежней сборкой не сравнивалось.
- Replay теряет операцию над пешкой, вошедшей между теми же тиками.
- CI на GitHub нет: `check` на Windows (детерминизм между ОС) — только локально у автора; стенд клиента на Windows
  не запускался.
- `DevCmd::Start` со списком игр не смотрит на `rounds`.
- Не измерен самый долгий кадр входа в раунд на слабом клиенте: дольше 3 с — сервер отключит игрока (у стенда
  таймаут связи 8 с, `--link-timeout`).
- Стенд: в логе тестов клиента `Could not set global logger` (ERROR) у всех клиентов процесса, кроме первого,
  `server_late_input_mismatch` от lightyear_debug и `Settings registry not found` — безвредно. Сервер стенда нельзя
  перезапустить в том же процессе (HTTP-поток держит порт): только `server_away`.
- Отчёт о падении в релизной сборке — с именами функций, но без строк (`strip = "debuginfo"` в `dist`); на Windows
  имена берутся из PDB, которого в установщике нет, — там, вероятно, по-прежнему без имён.
- Пороги в логах подобраны на глаз (`watch.rs`: поправка от 0,5 м; `stats.rs`: кадр от 250 мс, потери от 5%,
  RTT от 250 мс; сервер: разрыв ввода от 0,2 с) — подправить по первым реальным логам.
- В «Хвостиках» клиент откатывается почти на каждом снимке: замедление от захвата (`hold`), поворот к
  удерживаемому и замедление хвоста ставит сервер (`interact`, `tick` карты), а предсказание их не повторяет.
  Нажатия теперь не теряются, но откатов много; предсказывать замедление/поворот — отдельная работа.
- Без окна (`--offscreen`, `--fps 1000`) на Intel Gen9 запись F4/F9 даёт кадры по 300–500 мс (счётчик сцены раз в
  0,5 с, вероятно `generate_allocator_report`); в окне нет. Подробный F4 на Intel в окне не смотрели.
- `scenarios::the_owner_leaves_the_lobby` падал под нагрузкой `check` той же паникой часов — после правки не
  повторялся, но гонять ещё.
- Логи и трассы пишутся синхронно из главного цикла.
- `pkill -f fb_client` убивает и вызывающую оболочку: гасить `pkill -x fb_client` / `pkill -x fb_server`.
- Лицензия AGPL: сервер не показывает игрокам ссылку на свои исходники (§13 обязывает того, кто изменил сервер);
  SPDX-заголовков в файлах нет — лицензия задана `LICENSE` и `Cargo.toml`.
- Bevy 0.19 не размечает GPU-таймером проходы теней: в `GPU` оверлея их нет, цена — в sweep.
- Не сделано из прежних планов: `xtask trace / replay / new-game`, проверка
  графики на железе автора (60 FPS на «Низком» на HD 520/Vega 3, 144 на «Высоком» на GTX 1660), SSAO/TAA на T2,
  проход через портал, LOD на глаз.

## Проверка без окон

Автор не хочет окон и скриншотов на экране и смотрит интерфейс сам в своей игре: правки — сборкой и `check`, без
запусков. Если графику всё же надо проверить снимком — `fb_client --offscreen`.
