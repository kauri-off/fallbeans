# Состояние: с чего продолжать

Перезаписывается целиком в конце каждого треда. Только то, чего не видно в коде и git: где остановились, что
начато и не закончено, что сломано, с чего начать.

**6 октября 2026**, ветка `master`, последний коммит — `f3ccb62` (откаты ввода, часы, клики по краю кнопок).
Версия `0.1.0-alpha.1`. Последний TS-коммит помечен тегом `ts-final`. Протокол 20: сервер у автора, если он ещё из
`.deb` с протоколом 19, с новыми клиентами не сыграет — обновлять вместе.

Не закоммичено (протокол и симуляция не менялись) — система замеров рендера, `docs/perf.md`:
- `crates/fb_client/src/perf/`: оверлей F4 (строка → подробно с графиком, проходами GPU и сценой → профайлер),
  запись F9, sweep графики Shift+F9, бенчмарк `--perf-capture`/`--perf-sweep`; `cargo xtask perf run|show|compare|csv`.
- Профайлер — слой tracing над спанами `bevy/trace` (фича `profiler`, по умолчанию и в `dist`). В `LOG_FILTER`
  открыты спаны `bevy_ecs::system::function_system` и `bevy_ecs::schedule::schedule`; консольный и файловый лог
  фильтруют спаны (`fmt_layer` в `main.rs`, `logs.rs`), иначе каждая строка лога получила бы префикс системы.
- Профиль сборки `perf` (release без LTO, инкрементальный): правка клиента — 3 с вместо 77 с у release.
- Sweep нашёл падение Bevy 0.19: переход «TAA без SSAO» → «SSAO без TAA» оставлял у вида
  `BackgroundMotionVectorsPipelineId`, проход рисовал им в чужие цели — ошибка валидации wgpu, игра закрывалась.
  Обход — `drop_stale_background_motion` в `render/quality.rs`; игрок мог поймать это переключателями на «Высоком».
- `--fps` теперь задаёт частоту и для `--offscreen` (было жёстко 60), `--fullscreen`, `--no-gpu-timers`.

Проверено на железе автора без окна (`--offscreen`, RTX 5070 Laptop, Vulkan): бенчмарк и sweep пишут файлы,
настройки профиля после sweep не меняются, клиент на NVIDIA (nvidia-smi: процесс C+G, при снятом ограничении
40% загрузки, 1800 МГц). Без ограничения offscreen: 218 fps, GPU 1,3 мс, render CPU 4,1 мс — кадр упирается в CPU
рендер-мира, а не в видеокарту: с этого и начинать оптимизацию.

Постоянного сервера нет: игроки добавляют свой сервер в список на главном экране (`README.md`, «Свой сервер»).
У автора сервер стоит из `.deb` (systemd, логи в journald).

Не проверено вживую: оверлей F4 в окне (вид, график, читаемость), F9/Shift+F9 в окне, `cargo xtask perf run` с
окном и `--fullscreen`; четыре правки `f3ccb62` (и вид кнопок после разделения на оболочку и `Face`); окно, «Открыть
папку с логами» и F8 (автор смотрит сам); `cargo xtask dist nsis` с новой информацией о версии
(`VIProductVersion`, нет makensis на Linux); ползунки настроек при раскрытии/сворачивании «Графики» (бегунок
теперь ставится на место при создании, а не кадром позже).

## Начать с

1. Автору: `cargo xtask perf run` и `--sweep` на своём железе, F4 в игре; дальше — оптимизация CPU рендер-мира
   (профайлер F4 и `perf compare` до/после).
2. Автору: поиграть на новой сборке (60 Гц снимков, переписанная арифметика) — цифры ощущения в пределах базы,
   но вживую это не смотрели. Если ощущение поменялось, `cargo xtask audit --baseline` покажет, что именно.
3. Дальше гонять `cargo xtask fuzz-ui --secs 600 --jobs 4`; упавшее зерно → сценарий в `scenarios.rs` →
   исправление. Геймпада в monkey нет (стенд не шлёт его событий).
4. Автообновление вживую — на втором релизе (`version` → `0.1.0-alpha.2`, `release` по просьбе автора).
5. Открытые предложения аудита (`docs/audit/proposals.md`; сделанные помечены «Applied»): 5.6 геймпад в меню,
   7.2 закрепить `appimagetool`, 4.2 битый `settings.toml`, 2.2 повторы после пропуска тиков, 1.10 UDP по IPv6,
   1.5 ключ отладки не в URL.

## План: падения ловятся до запуска

Этапы 1–3 (стенд, сценарии, monkey) — в `8e65c0a`. Дальше, по выбору автора:

4. `stress` с полной логикой клиента (+ «Прервать игру», выход/вход, уход хоста). Сценарии и monkey уже закрывают
   эти действия на стенде (без задержек и потерь сети); вероятно, хватит флага задержки/потерь у сервера стенда.

## Не закончено и известные странности

Проблемы, описанные в `README.md`, здесь не повторяются.

- Иконка окна не задана (Bevy рисует свою): в Windows на панели задач и у exe нет иконки игры, ярлыки NSIS — с
  иконкой. На Linux иконка берётся из desktop-файла по app id `io.github.kauri_off.fallbeans`.
- Обход зависания Intel Gen9 (`INTEL_DEBUG=reemit`) в игру не встроен; `DeviceLost` клиент игроку не объясняет —
  выходит молча.
- `cargo xtask assets --export` пересобирает модели из Blender (AO вшивается серым PNG, у TS был JPEG — файлы
  чуть больше); закоммиченные модели — ещё из TS-конвейера, пересборка отложена автором.
- Допуски баланса ботов в `baseline.json` у карт на выживание широкие (первое выбывание ±5–9 с): разброс между
  сидами там большой, мелкие сдвиги ощущения на них база не поймает.
- `cargo xtask dist flatpak` добавляет пользовательский remote flathub (`--if-not-exists`).
- В соло-игре раунд кончается, как только единственный человек финишировал или выбыл: зрителя проверять двумя
  клиентами.
- Стресс с ботами в dev-сборке не проходит порог тика: гонять с `--release`. Первый прогон стресса сразу после
  сборки иногда ловит общее замирание на 0,1–0,6 с — повторить. У каждого клиента одна «необъяснённая»
  расходимость через ≈200–245 тиков после старта (в пределах порога); с прежней сборкой не сравнивалось.
- Replay теряет операцию над пешкой, вошедшей между теми же тиками.
- CI на GitHub нет: `check` на Windows (детерминизм между ОС) — только локально у автора; стенд клиента на Windows
  не запускался.
- `DevCmd::Start` со списком игр не смотрит на `rounds`.
- Не измерен самый долгий кадр входа в раунд на слабом клиенте: дольше 3 с — сервер отключит игрока (у стенда
  таймаут связи 8 с, `--link-timeout`).
- Стенд: в логе тестов клиента `Could not set global logger` (ERROR) у всех клиентов процесса, кроме первого,
  `server_late_input_mismatch` от lightyear_debug и `Settings registry not found` — безвредно. Сервер стенда нельзя
  перезапустить в том же процессе (HTTP-поток держит порт): только `server_away`.
- Отчёт о падении в релизной сборке — с именами функций, но без строк (`strip = "debuginfo"` в `dist`); на Windows
  имена берутся из PDB, которого в установщике нет, — там, вероятно, по-прежнему без имён.
- Пороги в логах подобраны на глаз (`watch.rs`: поправка от 0,5 м; `stats.rs`: кадр от 250 мс, потери от 5%,
  RTT от 250 мс; сервер: разрыв ввода от 0,2 с) — подправить по первым реальным логам.
- В «Хвостиках» клиент откатывается почти на каждом снимке: замедление от захвата (`hold`), поворот к
  удерживаемому и замедление хвоста ставит сервер (`interact`, `tick` карты), а предсказание их не повторяет.
  Нажатия теперь не теряются, но откатов много; предсказывать замедление/поворот — отдельная работа.
- Вход в раунд portal-panic на RTX 5060 Ti дал кадр 743 мс (лог автора): долгий кадр сборки карты не исследован.
- Логи и трассы пишутся синхронно из главного цикла.
- `pkill -f fb_client` убивает и вызывающую оболочку: гасить `pkill -x fb_client` / `pkill -x fb_server`.
- Лицензия AGPL: сервер не показывает игрокам ссылку на свои исходники (§13 обязывает того, кто изменил сервер);
  SPDX-заголовков в файлах нет — лицензия задана `LICENSE` и `Cargo.toml`.
- Bevy 0.19 не размечает GPU-таймером проходы теней: в `GPU` оверлея их нет, цена — в sweep.
- Не сделано из прежних планов: `xtask trace / replay / new-game`, проверка
  графики на железе автора (60 FPS на «Низком» на HD 520/Vega 3, 144 на «Высоком» на GTX 1660), SSAO/TAA на T2,
  проход через портал, LOD на глаз.

## Проверка без окон

Автор не хочет окон и скриншотов на экране и смотрит интерфейс сам в своей игре: правки — сборкой и `check`, без
запусков. Если графику всё же надо проверить снимком — `fb_client --offscreen`.
