# Производительность: замеры и профайлер

Всё ниже есть в обычной сборке игры (и в релизных пакетах): тестеру не нужны ни Tracy, ни сборка из исходников.

## Для тестеров

**F4** переключает оверлей по кругу: строка → подробно → профайлер → выключено.

Строка: `144 fps | frame 6.94 ms p99 9.1 | 1% low 118 fps | GPU 4.20 | CPU main 2.10 render 1.80 (wait 0.40) | GPU-bound`.

- `frame` — время кадра (среднее за 2 с), `p99` — 99-й перцентиль, `1% low` — частота кадров в самом медленном 1%.
  Если `1% low` сильно ниже `fps`, игра дёргается, даже когда средний fps высокий.
- `GPU` — время видеокарты на кадр (сумма размеченных проходов; Vulkan и DX12, на OpenGL не меряется).
- `CPU main` — логика игры, анимация, интерфейс; `render` — подготовка и отправка отрисовки (отдельный поток);
  `wait` — из него ожидание swapchain (видеокарта не успевает или ждём vsync).
- В конце — что держит кадр: `GPU-bound` (видеокарта), `CPU-bound (main)` / `CPU-bound (render)` (процессор),
  `vsync` (упёрлись в частоту монитора, запас есть), `fps limit` (ограничение из настроек), `mixed`.

Подробно: таблица avg/p50/p95/p99/max для каждой части кадра за 5 с, число фризов (кадр дольше двух медианных),
разрешение и масштаб FSR, пресет, видеокарта и драйвер; график последних 256 кадров (столбики: зелёный — до 60 fps,
жёлтый — до 30, красный — хуже; голубая линия — GPU; бледные линии — 60 и 144 fps); проходы видеокарты (время на
GPU и CPU, треугольники, фрагментов на пиксель — показатель перерисовки); сцена: сущности, меши (всего, в кадре, в
тени), треугольники, источники света, материалы, текстуры и их объём, буферы мешей, память видеокарты и процесса.

Профайлер: сколько миллисекунд за кадр уходит на каждое расписание (`Update`, `PostUpdate`, `Render`, …) и на 24
самых дорогих системы, сколько раз за кадр они запускались, ожидания acquire/present. Ниже — последние «длинные
кадры» (в 2,5 раза дольше обычного и дольше 25 мс) с тем, на что ушло время. Кадры дольше 100 мс с разбором
попадают и в лог.

**F9** — запись: идёт до следующего F9 (не дольше 5 минут). **Shift+F9** — замер графики: около минуты игра по очереди
выключает тени, AO, сглаживание, цветокоррекцию, частицы, включает FSR, понижает пресет — по 2 с на прогрев и 5 с на
замер каждого шага, без vsync и ограничения fps. Стойте на месте, чтобы картинка не менялась; F9 прерывает;
настройки возвращаются сами (и при выходе посреди замера). Пока идёт замер графики, «авто»-пресет не понижается.

Запись делится по сценам (меню, лобби, раунд каждой карты, подиум): у каждой свои времена кадра, профайлер и
счётчики сцены — `cargo xtask perf show` печатает их таблицей, длинные кадры подписаны сценой.

Результат — `perf-<время>.json` в папке логов (её открывает кнопка в настройках, пути — в README). Короткая сводка
пишется и в `client-<время>.log`. Пришлите json и скажите, где стояли и что было на экране.

## Для разработчиков

```
cargo xtask perf run [--map jump-club] [--secs 30] [--warmup 8] [--sweep] [--fullscreen] [--baseline файл.json]
cargo xtask perf show файл.json
cargo xtask perf compare база.json новый.json
cargo xtask perf csv файл.json [out.csv]
```

`run` поднимает сервер и один клиент в окне, хост запускает раунд карты с ботами, клиент играет сам (автопилот) и
через `--warmup` секунд раунда пишет замер без vsync и ограничения fps (или sweep), затем выходит; отчёт печатается,
файл — в `target/perf-runs/`. Меряются графические настройки профиля `perf` (`--profile` меняет): выставить их —
`fb_client --profile perf`, настройки. Автопилот и боты ходят по-разному, так что между прогонами ±несколько
процентов; сравнивайте p50 и GPU, повторяйте при сомнениях.

Профиль сборки по умолчанию — `perf` (`Cargo.toml`): код как в release, но без LTO и инкрементально. Пересборка
после правки клиента на машине автора — 3 с против 77 с у release (первая сборка профиля — 3 минуты). Цифры почти
те же, что у release; итог перед релизом сверить с `--cargo-profile release`. Собирать клиент и сервер одной
командой (`-p fb_client -p fb_server`, как это делает xtask): сборка одного пакета даёт другое объединение фич
зависимостей, и cargo пересобирает половину из них (2–3 минуты).

Все сцены подряд: `fb_client --start jump-club,portal-panic,hex-a-gone --start-rounds 3 --fill --perf-capture 110
--perf-from-start …` — `--start` берёт список карт (по очереди), `--perf-from-start` пишет с запуска, а не с разминки
раунда. Без `--autopilot` боб стоит на старте: кадр почти не меняется между прогонами (сид сервера `--seed 7`), это
удобнее для сравнения до/после, чем автопилот.

Встроенная видеокарта на ноутбуке с двумя GPU (AMD/Intel + NVIDIA): `--backend gl` с
`__EGL_VENDOR_LIBRARY_FILENAMES=/usr/share/glvnd/egl_vendor.d/50_mesa.json` — клиент рисует на встройке через Mesa
(тир T0, пресет Low). Для Vulkan на встройке AMD нужен пакет `vulkan-radeon`.

Без окна: `fb_client --offscreen --fps 1000 …` (`--fps` снимает ограничение 60 кадров offscreen) — так проверяется,
что всё считается, хотя swapchain там нет (`wait` = 0).

Флаги клиента: `--perf-capture SECS`, `--perf-sweep`, `--perf-warmup SECS`, `--perf-out PATH`, `--no-gpu-timers`
(без запросов timestamp/pipeline statistics — если драйвер с ними плохо работает), `--fullscreen`.

Глубже — внешние профайлеры (фичи клиента, не для релиза):

- `cargo run --profile perf -p fb_client --features tracy -- …` и [Tracy](https://github.com/wolfpld/tracy): все спаны
  систем и проходы GPU на одной шкале времени.
- `--features chrome`: файл `trace-*.json` (путь — `TRACE_CHROME=…`) для https://ui.perfetto.dev.

### Как это устроено

`crates/fb_client/src/perf/`: `mod.rs` — время кадра по частям (main: `First`…`Last`; render: расписание `Render`
на потоке рендера), `gpu.rs` — проходы из `RenderDiagnosticsPlugin` Bevy, `profiler.rs` — слой tracing, который
суммирует спаны систем Bevy (фича `profiler` = `bevy/trace`, включена по умолчанию и в `dist`), `scene.rs` —
счётчики сцены, `overlay.rs` и `graph.wgsl` — оверлей, `capture.rs` — запись и sweep.

Цена: спаны `bevy/trace` есть всегда (вход/выход в каждую систему через реестр tracing); суммируются они, только
пока открыт подробный режим или профайлер или идёт запись. Ожидания swapchain суммируются всегда (это два спана
за кадр).

### Ограничения

- Bevy 0.19 не размечает таймером проходы теней: их нет ни в списке проходов, ни в сумме `GPU`. Их цену показывает
  sweep (шаг `shadows off`).
- GPU-время приходит с опозданием на несколько кадров; для отдельного кадра оно приблизительное.
- На OpenGL нет pipeline statistics; GPU-время на Mesa radeonsi есть, на Intel (iris) — неверное (отрицательное).
- Без окна (`--offscreen`) у кадров нет обратного давления swapchain: при `--fps 1000` на Intel Gen9 запись F4/F9
  (счётчик сцены раз в 0,5 с) даёт кадры по 300–500 мс. В окне этого нет — Intel мерить в окне.
- Профайлер считает время включительно: система, запускающая расписание (`run_fixed_main_schedule`, откат
  Lightyear), включает время всех его систем.
