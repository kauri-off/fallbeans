1. **HTTP на axum** (`fb_server`, отдельный поток с tokio; к хабу — через канал, отвечает система в `Update`):
   `/fallbeans/health` (версия, сборка, `updating`, комнаты, игроки), debug API как `server/debugApi.ts`
   (`state` — порт `roomDebug.ts`, `logs`, `trace`, `replay` — `Room::debug_replay`, вход по `FB_DEBUG_KEY` →
   cookie: `auth.rs` уже умеет, сейчас помечено `expect(dead_code)`). Затем `/api/session`: connect token netcode
   с настоящим ключом и identity в user data (`ConnectToken::build` в `lightyear_netcode`), клиент берёт его по
   HTTPS перед подключением; вернуть `server_addr_check`; identity из hello убрать (`decisions.md`).
2. **Сборка раунда и навигации ботов вне тика**: `Room::next_round` строит арену прямо в тике (до 6 мс), сетка
   навигации строится при первом думании ботов. Строить следующий раунд заранее (за время результатов) и сетку
   во время интро; замерить стоимость тика с ботами 4 × 8 (`stress` с ботами: хосту — `ClientMsg::Fill(true)`
   или флаг клиента).
3. **Переподключение на любом транспорте** (сейчас только UDP → WS при `auto`): клиент при обрыве подключается
   снова тем же netcode id и с identity из `Ready` (`session.rs` уже шлёт токен и комнату); WS → UDP раз в минуту;
   таймаут netcode больше 3 с для WS через VPN. Потом стресс 4 × 8 на прод-хосте (`stress --remote --rooms 4`,
   проба уже понимает `--open-rooms`) — это ворота.

## Не закончено и известные странности

- Клиент: из событий карты применяет только бонусы (финиш, падения, события карт — Фаза 4); интерфейса комнат
  нет (Фаза 5) — только флаги `--room`, `--practice`, `--start`. Сообщения сервера пишутся в лог.
- Сервер держит игроков в «выживании» на респауне (`RoomOptions::eliminate = false` в `play.rs`): у клиента нет
  режима зрителя (Фаза 4). Тесты комнат идут с выбыванием, как TS.
- `--maintenance-file` работает, но деплой его не создаёт: при деплое клиенты по-прежнему просто теряют связь.
- Replay теряет операцию над пешкой, вошедшей между теми же тиками (ошибка TS, `decisions.md`): комната добавляет
  пешек посреди раунда только через `add_late_pawn` (dev `bot`), это операция — на практике не проявляется.
- Не разобрано: `jump-club` сид 1 — разница 5,6e-17 в золотом следе (на 437 других раундах — 0).
- Логи и трассы пишутся синхронно из главного цикла; `stress` делает `sync` после сборки, но запись на занятый
  диск всё ещё может заморозить процессы (`phases/2.md`).
- Классификатор `stress` записывает в «прочие» откат при первой синхронизации часов клиента (один на вход).
- Клиент не рисует `SceneItem::Special` (плитки hex-a-gone, стёкла hidden-bridge, порталы, барабаны…). Фазы 4/6.
