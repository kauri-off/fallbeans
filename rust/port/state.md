# Состояние переноса: с чего продолжать

Перезаписывается целиком в конце каждого треда и при закрытии фазы. Только то, чего не видно в коде и git:
где остановились, что начато и не закончено, что сломано, с чего начать. Сделанное сюда не переписывается.

**3 октября 2026**, ветка `rogue/port-to-rust`, последний коммит `54c7ce2`. Не закоммичено: отказ от «прода» —
`cargo xtask deploy` и `stress --remote` без хоста по умолчанию (`--host`, `--domain`, `--public-ip` или
`DEPLOY_*`), установщик без чужого домена и сайта, документы (`CLAUDE.md`, `rust/README.md`, `deploy/README.md`,
`plan.md`, ворота Фазы 3; `decisions.md`, «Постоянного сервера нет»). Автор коммитит сам.

Постоянного сервера нет: играем по локальной сети, сервер на машине автора (`rust/README.md`, «Игра по
локальной сети»). Деплой — только по просьбе автора и только на названный им хост.

## Начать с

1. **Игра по локальной сети** между двумя машинами (команды — `rust/README.md`): сервер `--dev --public-host
   <LAN-IP>`, клиенты `--room dev`, один с `--start <карта>`. Проверить UDP и `--transport ws`, переподключение
   (выдернуть сеть на 5–10 с), «игра обновляется» (`--maintenance-file`). Брать карты без `SceneItem::Special`:
   клиент их не рисует.
2. **Ворота Фазы 3** — стресс 4 × 8 с сервером в одном ядре и 300 МБ: `cargo xtask stress --release --clients 32
   --rooms 4 --secs 100` и с ботами (`--clients 16 --rooms 4 --client-arg=--fill`), сверить с разделом 11 (≤ 1 мс
   CPU на тик на комнату, процесс ≤ 60% ядра, RSS ≤ 300 МБ, 0 опоздавшего ввода). Ограничить надо только сервер:
   у `stress` нет флага для этого — добавить (например, обёртка `taskset -c 0` / `systemd-run --scope -p
   CPUQuota=100% -p MemoryMax=300M` для процесса сервера) или запускать сервер отдельно. Если на старте игры
   (первый раунд строится в тике) или в интро пик — вынести и их (`decisions.md`, «Следующий раунд строится в
   потоке»). Итог — в `phases/3.md`.
3. **WS → UDP:** клиент, ушедший на WS (`auto`), раз в минуту пробует UDP и возвращается, если тот стабилен
   (раздел 5, п. 3). Сейчас он остаётся на WS до конца сессии.

## Не закончено и известные странности

- Клиент: из событий карты применяет только бонусы (финиш, падения, события карт — Фаза 4); интерфейса комнат
  нет (Фаза 5) — только флаги `--room`, `--practice`, `--start`, `--fill`. Identity живёт в памяти процесса
  (`--token` — снаружи); файл настроек — Фаза 5.
- Сервер держит игроков в «выживании» на респауне (`RoomOptions::eliminate = false` в `play.rs`): у клиента нет
  режима зрителя (Фаза 4). Тесты комнат идут с выбыванием, как TS.
- Стресс с ботами в dev-сборке не проходит порог тика (p99 1,1 мс против 1 мс): гонять с `--release`. В release
  одно окно из 20 дало p99 1,16 мс посреди раунда — причина не найдена (`phases/3.md`).
- Первый прогон стресса сразу после сборки иногда ловит общее замирание всех процессов на 0,1–0,6 с (грязные
  страницы на диске, `phases/2.md`) — повторить прогон.
- Replay теряет операцию над пешкой, вошедшей между теми же тиками (ошибка TS, `decisions.md`): комната добавляет
  пешек посреди раунда только через `add_late_pawn` (dev `bot`), это операция — на практике не проявляется.
- Не разобрано: `jump-club` сид 1 — разница 5,6e-17 в золотом следе (на 437 других раундах — 0).
- Логи и трассы пишутся синхронно из главного цикла.
- Сессия по https через свой прокси со своим CA не проходит: `ureq` проверяет по встроенным корням (wss берёт
  системные). В локальной сети ходить напрямую по http/ws.
- `cargo xtask deploy` на этой машине не собирает сервер: нет цели `x86_64-unknown-linux-musl`.
- Классификатор `stress` записывает в «прочие» откат при первой синхронизации часов клиента (один на вход).
- Клиент не рисует `SceneItem::Special` (плитки hex-a-gone, стёкла hidden-bridge, порталы, барабаны…). Фазы 4/6.
