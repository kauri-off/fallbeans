## Начать с

1. **`cargo xtask bench`** — порт `scripts/bench.ts`: мс на тик и p99 по кускам 0,1 с после 3 с разогрева,
   разбивка по секциям (bots, physics, movers, rules, inputs, interact, map — нужна разметка в `Arena::step`),
   время сборки, память комнаты, комнат на ядро; сравнение с `bench/baseline.json` (снят на Windows — для
   сравнения переснять `bun run bench` на этой машине). Размер и кодирование снимка — через `fb_net::wire`,
   поэтому bench живёт в xtask (или отдельном бинарнике в `crates/`), а не в ядре. Harness — `fb_audit::harness`.
2. `cargo xtask trace / replay / new-game` с интерфейсом `bun run …` (`replay` уже есть в `fb_arena::record`,
   нужен CLI; `new-game` — заготовка модуля карты и регистрация в `fb_maps::GAMES`/`MAPS` и `golden!`).
3. CI: кросс-платформенный replay (одни записи → один `state_hash` на Windows и Linux) — последний пункт ворот
   вместе с bench.
