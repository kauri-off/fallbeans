# Фаза 3. Сервер

**Открыта 3 октября 2026**, параллельно с концом Фазы 2. **Закрыта 3 октября 2026.** Решения — в `../decisions.md`.

## Итог

**Ворота пройдены частично, остаток перенесён.** Стресс 4 × 8 в release с сервером на одном ядре и с
`MemoryMax=300M` без swap (`cargo xtask stress --release --limit-server`) проходит с цифрами раздела 11 с запасом:
тик всех четырёх комнат вместе p99 95–111 мкс без ботов и до 960 мкс с ботами (порог — 1 мс на комнату), CPU
сервера 4–6% ядра (порог 60%), RSS 64–69 МБ (порог 300), опоздавшего ввода 0–0,008% (таблица ниже, «Ворота»).
Игра по локальной сети между двумя машинами не проверена: нужен автор и вторая машина. Она перенесена в ворота
Фазы 4 — внутренний плейтест там и так идёт по локальной сети, с сервером на машине автора.

| Пункт фазы | Состояние |
| --- | --- |
| Hub, Room, director, awards, auth, axum, `GameClock`, dev-команды, флаг обновления | в коде; `rooms/tests.rs`, `auth.rs`, `director.rs`, `http.rs` |
| Переподключение на любом транспорте, удержание места 30 с, WS посреди игры и возврат на UDP | в коде; возврат на UDP проверен стрессом с `--udp-blocked` (замеры ниже) |
| Следующий раунд строится вне тика | в коде; первый раунд игры и тренировка — ещё в тике (до 6 мс) |
| Профиль CPU на VPS с 1 vCPU | своего VPS нет (`../decisions.md`, «Постоянного сервера нет»): ядро этой машины под `--limit-server` |
| Игра по локальной сети (UDP, WS, `auto`, обрыв, «игра обновляется») | перенесено в ворота Фазы 4 |

**Что перенесено**

- В ворота Фазы 4: игра по локальной сети между двумя машинами — UDP, `--transport ws`, `auto` (возврат на UDP),
  обрыв сети на 5–10 с, `--maintenance-file`.
- Замер старта игры на настоящем 1 vCPU (сборка первого раунда в тике) — когда у автора будет такой хост; пока его
  нет, в план не ставится.

## Замеры

**Стресс с комнатами** (3 октября, эта машина, dev-сборка; RTT 150 мс, джиттер 30, потери 5%, 100 с, UDP; jump-club
без выбывания, ботов нет):

| | 1 комната × 8 | 4 комнаты × 8 |
| --- | --- | --- |
| Опоздавший ввод | 0% у всех | 0–0,008% |
| Прочие расхождения в минуту | 0–0,6 (откат при входе) | 0–1,2 |
| Тик (все комнаты), p99 / max | 160 мкс / 5,9 мс | 353 мкс / 1,6 мс |
| Трафик к игроку | 13,4 КБ/с | 13,4 КБ/с |
| CPU / память сервера | 0,5% / 70 МБ | 0,8% / 76 МБ |

Max 5,9 мс — тик, в котором собирается следующий раунд (сборка карты в тике). Тренировка с 3 ботами (door-dash):
тик p99 1,9 мс, max 5,9 мс в первые секунды раунда — сетка навигации ботов строится в тике.

**Стресс с ботами, раунд строится в потоке** (3 октября, эта машина, release; RTT 150 мс, джиттер 30, потери 5%,
100 с, UDP; 4 комнаты по 4 игрока и 4 бота (`--client-arg=--fill`), jump-club):

| | |
| --- | --- |
| Опоздавший ввод | 0% у всех |
| Прочие расхождения в минуту | 1,8–9,1 (боты толкают игроков; без ботов 0–1,2) |
| Тик (все комнаты), окна по 5 с | mean 85–112 мкс, p99 230–390 мкс; одно окно из 20 — p99 1,16 мс, max 3,4 мс посреди раунда (не сборка, причина не найдена) |

**Ворота: стресс 4 × 8, сервер как на 1 vCPU** (3 октября, эта машина, release, `--limit-server`: сервер один на
ядре 31 в scope с `MemoryMax=300M` без swap, клиенты на ядрах 0–30; RTT 150 мс, джиттер 30, потери 5%, 100 с,
UDP, jump-club; CPU — доля одного ядра):

| | 4 комнаты × 8 игроков | 4 комнаты × (4 игрока + 4 бота) |
| --- | --- | --- |
| Опоздавший ввод | 0–0,008% | 0% |
| Прочие расхождения в минуту | 0–0,6 | 0,6–4,2 |
| Тик (все комнаты), окна по 5 с | mean 63–67 мкс, p99 95–111 мкс, max 319 мкс | mean 69–103 мкс, p99 218–960 мкс, max 5,5 мс |
| CPU сервера | 5,6–6,4% ядра | 3,8–4,8% ядра |
| RSS сервера | 64–68 МБ | 64–69 МБ |
| Трафик к игроку | 13,3 КБ/с | 13,4 КБ/с |

Цифры раздела 11 выполнены с запасом: ≤ 1 мс на тик на комнату (здесь все 4 вместе), ≤ 60% ядра, ≤ 300 МБ, 0
опоздавшего ввода. Ядро этой машины быстрее vCPU маленького VPS (на VPS в Фазе 0: 7% ядра в простое).

**Пики тика с ботами — A\*** (3 октября, release, jump-club с 8 ботами, 5 сидов, без сети; счётчики в
`nav.path` на время замера): все боты комнаты думают в одном тике (каждый 6-й, `BOT_EVERY`, как в TS), и каждый
перестраивает маршрут раз в ~0,6 с или сойдя с него. Поиск — ~0,3 мкс на раскрытый узел; тик с 2–5 поисками на
1200–2000 узлов — 0,4–0,6 мс, один неудачный поиск до предела (2500 узлов) — 0,8 мс. Худший случай — восемь
неудачных поисков в одном тике, ~6 мс; max 5,5 мс в стрессе — он же (или совпавшие тики дум нескольких комнат).
Разносить ботов по тикам нельзя без расхождения с TS (`audit --vs-ts`); ускорять — только сам поиск с тем же
порядком раскрытия.

**Возврат с WS на UDP** (3 октября, dev, 2 клиента `auto`, RTT 150 мс, джиттер 30, потери 5%, 110 с,
`--udp-blocked`): UDP закрыт 20 с — вход по WS через 2 с, проба на 61-й секунде, переход в первых результатах
(~80 с), место сохранено (`resumed`), новое соединение за 0,4–0,6 с, 0 опоздавшего ввода, по одному «прочему»
расхождению на переподключение. UDP закрыт всё время — проба не прошла, клиент остался на WS без разрыва.
